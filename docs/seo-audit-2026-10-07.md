# Revisión de indexación de NovasPlay — 7 de octubre de 2026

Sitio revisado: https://novasplay.neocharge.app/

## Comprobaciones en el sitio publicado

- La portada, el catálogo y la página de Free Fire respondieron HTTP 200 con texto prerenderizado, título, canonical correcto y meta robots `index,follow`.
- `robots.txt` permite el rastreo y apunta al sitemap. El sitemap responde HTTP 200 y contiene las cinco páginas públicas.
- HTTP redirige a HTTPS. `/catalogo` redirige permanentemente a `/catalogo/`.
- `/no-existe-auditoria-seo` devuelve HTTP 200 y el mismo HTML de la portada. Es una respuesta incorrecta para una dirección inexistente, compatible con un problema de soft 404. No demuestra por sí sola que sea el motivo de exclusión de la portada.
- `/profile` y `/checkout/1` tienen una cabecera `X-Robots-Tag: noindex, nofollow`, aunque el HTML servido inicialmente es el de la portada y contiene `index,follow`.
- El catálogo de productos de la portada se carga en el navegador. Hay texto explicativo prerenderizado, pero no todas las fichas de productos están en el HTML inicial.
- El código oculta secciones con `opacity: 0` hasta que un observador las marca visibles. Esto hace que su visibilidad dependa del navegador y de la posición de la pantalla.

## Cambios preparados

- Se elimina la regla global de Cloudflare que reescribía cualquier URL a la portada. Las rutas de cuenta, compra y callback de Google conservan reglas explícitas al cliente de Angular.
- Se añade `404.html` para que Cloudflare Pages responda 404 en rutas desconocidas, en lugar de activar su fallback automático de aplicación de una sola página.
- Angular dispone de una página de error propia y una respuesta 404 para la ruta desconocida en el servidor.
- La plantilla del cliente usada para rutas privadas lleva `noindex` y no declara la portada como canonical. Se prepara automáticamente después de `npm run build`.
- Las secciones de contenido son visibles desde el HTML inicial, sin esperar scroll o hidratación.
- Los metadatos sociales se actualizan también al regresar a la portada y al abrir términos o una página inexistente.
- El servidor Node normaliza las URL públicas con barra final, revalida HTML/sitemap/robots y declara los hosts permitidos. Durante las pruebas, la falta de hosts provocó un fallback a una plantilla vacía con HTTP 200.

## Validación y publicación

Pruebas realizadas: compilación de producción correcta; comprobaciones de los cinco HTML y sitemap correctas; comprobaciones HTTP correctas en el servidor Node y en el emulador oficial de Cloudflare Pages (Wrangler). En navegador se verificó la página 404, su enlace al catálogo, el acceso directo al perfil y el regreso a la portada con meta `index,follow`, canonical correcto y las siete secciones visibles sin scroll.

También se verificaron diez variantes de rutas privadas (con y sin barra final) y su conservación de URL: HTTP 200 y `noindex`, sin redirección a la plantilla. Cuatro rutas o archivos inexistentes devolvieron 404. No se hicieron compras ni se validó el backend comercial con la configuración local.

Ejecutar `npm run build` y `npm run check:seo`. Para probar HTTP, iniciar el servidor generado y ejecutar `npm run check:seo -- http://localhost:4401` con el puerto elegido.

La compilación local usa el backend de desarrollo configurado por defecto. No subir este `dist` directamente a producción. El alojamiento debe reconstruir desde el código con su `API_URL` de producción existente y ejecutar `npm run build`, incluido su paso `postbuild`.

Si el alojamiento es Cloudflare Pages, el directorio estático es `dist/NovasPlay/browser`. Verificar después de publicar que las cinco páginas públicas respondan 200; las inexistentes, 404; y que las rutas directas de compra, perfil y callback sigan disponibles. Un Worker o reglas externas que reescriban todas las rutas a la portada tendrían que corregirse también; no se han inspeccionado los ajustes de la cuenta.
